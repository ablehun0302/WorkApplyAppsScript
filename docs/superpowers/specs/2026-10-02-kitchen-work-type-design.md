# 주방보조 근무형태·시간대 신청 설계

작성일: 2026-10-02

## 목적

`주방보조_전국`은 주간/야간으로 나뉘는 현장이 아니라, 파트타임인지 풀타임인지와 몇 시부터
몇 시까지 가능한지가 배치 기준이다. 지금 신청 화면은 모든 근무지에 주간/야간 버튼만
보여주므로 이 정보를 받을 방법이 없다.

근무지가 `주방보조_전국`인 날짜에 한해, 주간/야간 버튼 대신 근무형태(파트타임/풀타임)
하나와 가능한 시간대(시작~종료)를 날짜마다 입력받는다. 관리자는 이 값을 주간 표와 배치
문자에서 보고, 근무자 추가·수정·신규 승인 창에서 직접 고칠 수 있다.

## 핵심 결정

**주방보조 날짜는 기존 주간 칸을 켠 채로 저장하고, 근무형태·시간만 덧붙인다.**

지금 시스템은 날짜의 `day`나 `night`가 켜져 있어야 "신청한 날"로 본다. 관리자 주간 표,
목표 인원, 배치(Assign), 이력(History), 신청 취소 처리(`removeCanceledAssignments_`)가
모두 이 두 값을 기준으로 돈다. 주방보조 신청을 `day: true`로 저장하면 이 전부가 수정 없이
동작하고, 주방보조 신청자는 관리자 주간 표에 나온다.

주간/야간과 별개인 세 번째 구분을 만드는 방법은 택하지 않는다. `day || night`를 전제로 한
코드 30여 곳과 Assign·Target 시트의 키 구조(`날짜_시프트_key`)를 모두 바꿔야 한다.

## 데이터 모델

`Data`·`신규데이터` 시트 F열 `shiftsJSON`:

```js
[{ date: "2026-10-05", day: true, night: false,
   workType: "Part", timeFrom: "10:00", timeTo: "15:00" },                      // 주방보조
 { date: "2026-10-06", day: true, night: false,
   workType: "Full", timeFrom: "22:00", timeTo: "02:00", location: "주방보조_전국" }, // 그날만 주방보조, 자정 넘김
 { date: "2026-10-07", day: true, night: true }]                                // 다른 근무지
```

| 필드 | 값 | 비고 |
|---|---|---|
| `workType` | `"Part"` \| `"Full"` | 화면에는 파트타임/풀타임(짧게는 파트/풀)으로 표시 |
| `timeFrom` | `"HH:MM"`, 00:00~23:30 | 30분 단위 |
| `timeTo` | `"HH:MM"`, 00:30~24:00 | 30분 단위 |

규칙:

- 세 필드는 그 날짜의 실효 근무지가 `주방보조_전국`일 때만 의미가 있다. 다른 근무지의
  날짜에 남아 있어도 무시한다.
- 주방보조 날짜는 항상 `day: true, night: false`다. 주방보조에는 야간 신청이 없다.
- `timeFrom`과 `timeTo`는 달라야 한다. `timeTo`가 `timeFrom`보다 이르면 자정을 넘기는
  시간대로 본다(22:00~02:00). 별도 플래그는 두지 않는다.
- 풀타임도 시간을 반드시 입력한다.
- 시트 열 추가와 기존 데이터 변환은 없다. 기존 주방보조 신청은 `workType`이 없는 채로
  남고, "근무형태 미입력"으로 취급한다.

## 공용 코드 (`SharedScript.html`)

신청 화면과 관리자 창 세 곳(근무자 추가, 근무자 수정, 신규 승인 수정)이 같은 줄을 그리므로
한 곳에 둔다.

- 상수: `KITCHEN_LOCATION = '주방보조_전국'`, `WORK_TYPES = { Part: '파트타임', Full: '풀타임' }`.
- **표기 함수** `kitchenShiftLabel(shift)` → `"파트 10~15"`, `"풀 9~18"`, `"파트 10:30~15"`,
  `"풀 22~2"`. 정각은 분을 떼고 앞자리 0을 뗀다. 시간이 없으면 `"파트"`만, `workType`이
  없거나 모르는 값이면 빈 문자열.
  - 신청 저장은 로그인 없이 호출되므로 `workType`·시간에 임의 문자열이 들어올 수 있다. 이
    함수는 `WORK_TYPES`에 있는 값과 30분 단위 시간 목록에 있는 값만 출력한다. 관리자 화면은 이
    함수의 결과만 HTML에 넣는다.
- **전환 함수** `applyKitchenMode(sel, isKitchen)`: 한 날짜의 선택 상태를 근무지에 맞게 맞춘다.
  - 주방보조가 됨: 주간이나 야간이 켜져 있고 `workType`이 없으면 `workType: 'Part'`,
    `day: true`, `night: false`, 시간은 빈 값. 신청이 없던 날짜는 그대로.
  - 주방보조가 아니게 됨: `workType`이 있으면 `day: true`를 유지하고 `workType`·시간을 지운다.
- **줄 그리기 함수**: 근무형태 버튼 두 개와 시작/종료 `<select>`의 HTML을 만든다. 화면마다
  다른 id 접두어와 비활성 여부를 인자로 받는다. 근무형태 버튼은 기존 `.shift-btn` 스타일을 쓴다.
- **검사 함수** `kitchenTimeError(sel)`: 신청된 주방보조 날짜에 시간이 비었거나 시작과 종료가
  같으면 true.

## 근무자 신청 화면 (`WorkerView.html`)

그 날짜의 근무지(`selections[key].location || currentBaseLocation()`)가 `주방보조_전국`이면
주간/야간 버튼 대신 아래를 그린다.

```
10/5 (월)  [주방보조_전국 ▾]
  [■파트타임■] [ 풀타임 ]
  [10:00 ▾] ~ [15:00 ▾]
```

- 근무형태 버튼을 누르면 그 날짜가 신청된다(`workType` 설정, `day: true`). 선택된 버튼을 다시
  누르면 신청 취소다. 파트타임과 풀타임은 하나만 선택된다.
- 시간 선택은 근무형태를 고른 날짜에만 보인다.
- 날짜별 근무지 드롭다운은 지금처럼 신청된 날짜에만 보인다. 주방보조 줄에서는 "근무형태가
  선택됨"이 신청 여부다. 신청을 취소하면 지금처럼 날짜별 근무지 지정도 함께 지운다.
- 기본 근무장소 라디오나 날짜별 근무지 드롭다운이 바뀌면, 영향받는 줄에 전환 함수를 적용하고
  줄을 다시 그린다.
- 기존 신청을 불러올 때도 전환 함수를 거친다. `workType` 없이 저장돼 있던 주방보조 날짜는
  파트타임이 선택되고 시간이 빈 상태로 나온다.
- 지난 날짜는 지금처럼 비활성으로 표시만 한다.

저장(`submitApplication`):

- 주방보조 날짜는 `{date, day: true, night: false, workType, timeFrom, timeTo}`로 보낸다.
  날짜별 근무지 예외(`location`) 규칙은 그대로다.
- 오늘 이후의 신청된 주방보조 날짜 중 검사 함수에 걸리는 것이 있으면 저장하지 않고
  "10/5(월) 주방보조 근무 시간을 선택해주세요."처럼 첫 날짜를 알려준다. 지난 날짜는 서버가
  기존 값을 유지하므로 검사하지 않는다.
- 신규 신청 안내 문구("근무할 날짜의 (주간/야간)을 눌러 주세요")는 바꾸지 않는다.

## 관리자 화면 (`AdminView.html`)

### 주간 표

`buildWorkerWeekShiftTable`의 주간 표에서, 그 날짜의 근무지(`locationOfDate`)가 주방보조이고
신청에 `workType`이 있으면 요일 글자 아래에 `파트 10~15`를 작은 글씨로 적는다. 배치정보
라벨(`.mark-label`)과 구분되는 색의 클래스를 `SharedStyles.html`에 추가한다.

배치정보 수정 대기 표시(`applyInfoCellPendingStyle`)가 칸 내용을 다시 그릴 때도 이 표기가
사라지지 않아야 한다.

야간 표, 목표 인원, 배치판 구조는 바꾸지 않는다. 주방보조 탭의 야간 표는 빈 채로 둔다.

### 근무자 추가·수정 창, 신규 승인 수정 창

세 창의 날짜 목록에서 그 날짜의 근무지가 주방보조이면 공용 줄 그리기 함수로 근무형태 버튼과
시간 선택을 보여주고, 관리자가 고칠 수 있다.

| 창 | 그 날짜의 근무지 판정 |
|---|---|
| 근무자 수정 | `effectiveLocation(rec, 날짜)` |
| 근무자 추가 | 불러온 일정의 `location` → 폼에서 고른 근무지 라디오 |
| 신규 승인 수정 | 신청의 `location` → 창에서 고른 근무지 |

- 세 창 모두 날짜 목록을 그릴 때 전환 함수를 거친다. `workType` 없이 저장돼 있던 주방보조
  날짜는 신청 화면과 마찬가지로 파트타임·시간 미입력으로 나오고, 시간을 채워야 저장된다.
- 근무자 추가 창과 신규 승인 수정 창은 근무지 선택이 바뀌면 전환 함수를 적용하고 날짜
  목록을 다시 그린다.
- 저장할 때 주방보조 날짜는 `workType`·`timeFrom`·`timeTo`를 포함해 보낸다. 시간 검사는
  신청 화면과 같고, 걸리면 해당 창의 메시지 영역에 날짜를 알려준다.
- 근무자 추가 창에서 기존 근무자를 불러올 때 관리자 지정 근무지(H열)가 폼의 라디오보다
  우선하는 기존 동작은 그대로다.

### 신규 신청 요약

`pendingShiftSummary_`에서 주방보조 날짜는 `10/5(월) 주간` 대신 `10/5(월) 파트 10~15`로
적는다. `workType`이 없으면 지금처럼 주간/야간으로 적는다.

### 배치 문자

`buildShiftText`와 배치판 목록에서, 배치된 사람의 그 날짜 신청이 주방보조이고 `workType`이
있으면 이름 줄 끝에 붙인다.

```
남1.김OO_1층 (파트 10~15)
```

### 주간 표의 날짜 켜고 끄기

신청날짜 수정 모드(`buildNewShifts`)는 기존 신청을 `{date, day, night}`로 다시 만든다. 이때
`workType`·시간이 사라지지 않게 서버 병합에서 되살린다(아래). 이 모드로 주방보조 날짜를 새로
켜면 `workType`이 없는 주간 신청이 되고, 관리자가 근무자 수정 창에서 채운다.

## 서버 (`WorkSystemSheet.gs`)

`mergeShiftLocations_`는 관리자 화면이 `{date, day, night}`만 보내도 날짜별 `location`이
지워지지 않게 기존 값을 되살린다. 같은 규칙을 `workType`·`timeFrom`·`timeTo`에 적용한다.

- 새 값에 `workType`이 있으면 새 값의 세 필드를 그대로 쓴다.
- 새 값에 `workType`이 없고 같은 날짜의 기존 값에 있으면 세 필드를 되살린다.

이름이 하는 일과 맞지 않게 되므로 `mergeShiftExtras_`로 바꾸고 호출부 세 곳
(`batchSaveRecords`, `approvePending`, `adminUpdateShifts`)을 함께 고친다.

근무자의 `saveRecord`·`savePendingRecord_`는 클라이언트가 보낸 shifts를 그대로 저장하므로
바꾸지 않는다.

## 범위 밖

- 관리자 근무 통계 달력의 주/야간 표기.
- 주방보조 탭에서 야간 표를 숨기는 것.
- 주방보조 전용 목표 인원이나 시간대별 집계.
- 기존 주방보조 신청 데이터의 일괄 변환.

## 검증

저장소에 자동 테스트가 없다. 화면과 무관한 함수(표기, 전환, 검사, 서버 병합)는 Node로 실행하는
작은 스크립트로 입력과 출력을 확인한다.

- 표기: 정각/30분, 앞자리 0, 자정 넘김, 시간 없음, 모르는 `workType`, 형식이 틀린 시간
  (`"<b>"` 등)이 빈 문자열로 떨어지는지.
- 전환: 주간만/야간만/둘 다/신청 없음 → 주방보조, 주방보조 → 다른 근무지.
- 검사: 시간 비어 있음, 시작=종료, 자정 넘김 허용.
- 병합: `workType` 없는 새 값에 기존 값 복원, 있는 새 값은 덮어씀, `location` 복원은 그대로.

구현하면서 화면 로직도 같은 스크립트(`tests/kitchen-work-type.test.js`)에서 가짜 DOM으로 돌려 확인하게 했다.
신청 화면의 줄 전환·저장 값·저장 전 검사, 관리자 창 세 곳의 전환·저장 값, 주간 표·신규 신청 요약·배치 문자
표기가 여기에 들어 있다. 실제 브라우저에서의 모양과 클릭 동작은 배포 후 직접 확인한다.

1. 기본 근무장소를 주방보조로 고르면 모든 날짜 줄이 근무형태 버튼으로 바뀐다.
2. 근무형태를 고르면 시간 선택이 나오고, 시간을 비우고 저장하면 날짜를 알려주며 막힌다.
3. 22:00~02:00을 저장하고 다시 조회하면 그대로 나온다.
4. 다른 근무지가 기본인 사람이 하루만 주방보조로 바꾸면 그 줄만 바뀌고, 저장 후 유지된다.
5. 관리자 주방보조 탭 주간 표에 `파트 10~15`가 보이고, 배치 문자에도 붙는다.
6. 근무자 수정 창에서 풀타임으로 바꿔 저장하면 주간 표에 반영된다.
7. 신청날짜 수정 모드로 다른 날짜를 켜고 꺼도 기존 주방보조 날짜의 근무형태·시간이 남는다.
8. 신규 신청자가 주방보조로 신청하면 승인 패널 요약에 표기되고, 수정 후 승인으로 고칠 수 있다.
9. 주방보조가 아닌 근무지의 신청·수정·배치가 이전과 똑같이 동작한다.
