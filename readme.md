ApplyWorkerSite: 근무신청 사이트

공용 스크립트: WorkSystemSheet.gs

`AdminNotifyFunction/`: 근무 신청 시 관리자 알림 문자용 별도 Cloud Function (아래 참고)

## 알려진 이슈 / 계획

- **근무 신청 시 관리자 알림**: 근로자가 근무 신청하면 관리자에게 문자를 보내고 싶은데, `saveRecord`(신청 저장 함수)가 원래 인증 없는 공개 함수라 GAS 안에서 신청 저장 직후 바로 알림을 보내면 존재하지 않는 (이름,PIN)으로 반복 호출해 관리자 폰 스팸 + SOLAPI 크레딧을 무한정 소모시킬 수 있음. GAS의 시간 기반 트리거로 우회하려 해도, 트리거 함수는 반드시 톱레벨이어야 해서 결국 `google.script.run`으로 클라이언트가 직접 호출 가능해지고, 그러면 "5분 배치"로 묶은 의미가 없어짐(클라이언트가 원할 때마다 배치 함수를 직접 불러 즉시 발송시킬 수 있음).
  - **결정 및 구현**: 알림 발송부를 GAS 웹앱과 완전히 분리된 **Google Cloud Scheduler → Cloud Function(Pub/Sub 트리거, HTTP 엔드포인트 없음)**로 뺐다 (`AdminNotifyFunction/`). 5분마다 `Data` 시트를 읽어 아직 알리지 않은(= `notifiedAt`(M열)이 비어있는) 신규 신청 행을 찾아 SOLAPI로 발송하고 M열에 발송 시각을 기록해 중복 발송을 막는다. 별도 DB 없이 시트 자체를 상태 저장소로 씀. HTTP로 노출되지 않으므로 워커/관리자 웹앱 클라이언트가 원천적으로 호출할 방법이 없음. GAS 쪽 코드는 건드리지 않음(`saveRecord`에서 알림을 직접 호출하지 않음).
  - **배포는 아직 안 함** — 이 세션에 gcloud CLI가 없어서 코드와 배포 스크립트(`AdminNotifyFunction/DEPLOY.md`)만 준비해뒀고, GCP 프로젝트 생성/시크릿 등록/실제 배포는 사용자가 직접 실행해야 함.
  - 이 구조는 "알림 발송 자체를 클라이언트가 실행하는 것"만 막을 뿐, `saveRecord`가 여전히 인증 없이 가짜 신청을 무한정 만들 수 있다는 근본 문제는 해결하지 않음. 근본 해결책은 신청자 휴대폰 OTP 인증(신규 신청 시에만 요구) — 별도 작업으로 남겨둠.
