# GetWorkerIdSite 설계 (최초 작성: 2026-08-26)

## 목적

새로 채용된 근로자가 로그인 없이 접속해 이름·연락처와 함께 신분증, 통장사본, 보건증, 기타 서류 사진/PDF를 업로드하면, 구글 드라이브에 `{이름}_{연락처}` 폴더를 만들어(또는 재사용해) 그 안에 저장하는 공개 페이지.

## 프로젝트 구조

기존 사이트들과 마찬가지로 **완전히 독립된 새 GAS 프로젝트**로 만든다. 인증이 없는 공개 업로드 페이지이고 스프레드시트를 전혀 사용하지 않으므로, 기존 `WorkSystemSheet.gs` 공용 데이터 계층은 재사용하지 않는다.

```
D:\WorkApplyWebsite\
  GetWorkerIdSite\
    Code.gs        # doGet() 진입점만
    Upload.gs      # 폴더 생성/재사용, 파일 저장 로직
    index.html     # 업로드 폼 UI + 클라이언트 로직
    docs\
      DESIGN.md    # 본 문서
```

## 접근 권한

인증 없음(공개). 새 근로자에게 배포 URL만 공유하면 누구나 접속해 자기 이름으로 서류를 업로드한다. 관리자 화면이나 비밀번호는 없다.

## 업로드 항목

| 항목 | 필수 여부 | 항목당 파일 수 |
|---|---|---|
| 이름 | 필수 | - |
| 연락처 | 필수 | - |
| 신분증 | 필수 | 여러 개 허용 |
| 통장사본 | 필수 | 여러 개 허용 |
| 보건증 | 선택 | 여러 개 허용 |
| 기타 서류 | 선택 | 여러 개 허용 |

허용 파일 형식: 이미지(`image/*`), PDF(`application/pdf`). 파일당 최대 10MB.

## 동명이인 처리

구글 드라이브 폴더명을 `{이름}_{연락처}`로 구성해 이름이 같아도 연락처로 구분한다. 같은 이름+연락처로 재접속해 다시 제출하면 새 폴더를 만들지 않고 기존 폴더에 파일을 추가한다(실수 재제출/보정 제출을 자연스럽게 지원).

## 업로드 방식: 폴더 먼저 생성 후 파일별 개별 업로드

항목당 여러 파일을 허용하고 파일당 최대 10MB까지 허용하므로, 한 번에 모든 파일을 하나의 `google.script.run` 호출로 보내면(일괄 제출 방식) 총 payload가 커져 타임아웃/실패 위험이 크다. 대신:

1. 폼 제출 시 먼저 `getOrCreateWorkerFolder(name, phone)`를 1회 호출해 폴더 ID를 얻는다.
2. 이후 선택된 파일마다 `uploadFile(folderId, category, base64Data, mimeType, fileName)`을 개별 호출로 순차 업로드한다.
3. 클라이언트는 파일별 진행 상태(대기/성공/실패)를 표시하고, 실패한 파일만 재시도할 수 있게 한다.

## 서버 함수 (Upload.gs)

- `getOrCreateWorkerFolder(name, phone)`
  - Script Properties의 `ROOT_FOLDER_ID` 아래에서 `{이름}_{연락처}` 이름의 폴더를 찾고, 없으면 새로 생성
  - 이름/연락처가 비어 있으면 에러
  - 폴더 ID(string) 반환
- `uploadFile(folderId, category, base64Data, mimeType, fileName)`
  - `mimeType`이 `image/*` 또는 `application/pdf`가 아니면 에러
  - 디코딩한 바이트 크기가 10MB를 초과하면 에러
  - 파일명을 `{category}_{fileName}` 형식으로 만들어 (예: `신분증_photo1.jpg`) 해당 폴더에 저장
  - 저장된 파일의 이름/ID를 반환

### `Code.gs`
```javascript
function doGet() { ... } // index.html 렌더링, 인증 없음
```

## 클라이언트 흐름 (index.html)

1. 이름/연락처 입력 + 신분증(필수)/통장사본(필수)/보건증(선택)/기타서류(선택) 파일 선택 input (각 `multiple` 속성으로 항목당 다중 선택)
2. 제출 버튼 클릭 시:
   - 필수 항목(이름, 연락처, 신분증 최소 1개, 통장사본 최소 1개) 확인, 누락 시 안내 문구 표시 후 중단
   - 선택된 모든 파일에 대해 크기(10MB)·형식(이미지/PDF) 클라이언트 검증, 위반 파일은 목록에서 바로 표시
3. `getOrCreateWorkerFolder(name, phone)` 호출 → 폴더 ID 획득
4. 전체 파일 목록을 순회하며 `uploadFile`을 순차 호출, 파일별 상태를 UI에 업데이트(대기 → 업로드 중 → 성공/실패)
5. 완료 후 결과 요약(성공 N건 / 실패 N건) 표시. 실패한 파일에는 개별 "재시도" 버튼 제공(같은 폴더 ID로 `uploadFile` 재호출)

## Script Properties (GetWorkerIdSite 프로젝트 전용)

| 키 | 용도 | 비고 |
|---|---|---|
| `ROOT_FOLDER_ID` | 근로자별 폴더를 생성할 상위 Drive 폴더 ID | 미설정 시 `getOrCreateWorkerFolder`가 명확한 에러를 던짐 |

## 배포 설정

Apps Script 편집기에서 "배포" → "새 배포"로 실제 배포할 때 반드시 다음 두 값으로 설정한다:

- **실행(Execute as)**: 나(소유자) — 그래야 `DriveApp` 호출이 스크립트 소유자 권한으로 실행되어 `ROOT_FOLDER_ID`에 접근할 수 있다
- **액세스 권한(Who has access)**: 모든 사용자(익명 사용자 포함) — 로그인 없는 공개 페이지이므로 필수

이 설정을 빠뜨리면 익명 방문자가 접속할 때마다 "ROOT_FOLDER_ID가 올바르지 않습니다" 에러가 뜬다(방문자 권한으로 `DriveApp`이 실행되어 폴더에 접근할 수 없기 때문). "테스트 배포"는 항상 개발자 권한으로 실행되므로 이 문제를 재현하지 못한다 — 반드시 실제(신규) 배포로 무기명 브라우저(시크릿 창)에서 확인해야 한다.

## 범위 밖 (단순성 우선, 필요 시 추후 확장)

- 제출 현황을 스프레드시트 등에 별도로 기록 — 구글 드라이브에 이름별 폴더가 생기는 것 자체로 충분하다고 판단
- 관리자 인증/조회 화면
- 업로드된 서류의 열람·삭제 기능
- 동시 업로드에 대한 락(LockService) — 개인별 업로드라 동시성 충돌 가능성이 낮음

## 에러 처리

- 필수 항목 누락: 제출 전 클라이언트에서 막고 안내 문구 표시
- 파일 형식/크기 위반: 클라이언트에서 선택 시점에 걸러내고, 서버(`uploadFile`)에서도 재검증해 위반 시 해당 파일만 실패 처리(전체 제출을 막지 않음)
- `ROOT_FOLDER_ID` 미설정/잘못된 값: `getOrCreateWorkerFolder`가 명확한 에러를 던져 UI에 "관리자에게 문의" 안내 표시
- 개별 `uploadFile` 실패(네트워크/Drive 오류/quota): 해당 파일만 실패로 표시하고 나머지 파일 업로드는 계속 진행. 실패한 파일은 재시도 버튼으로 재업로드 가능

## 테스트 체크리스트 (수동, GAS 특성상 자동화 테스트 없음)

1. 신분증/통장사본 없이 제출 시 클라이언트에서 막히는지 확인
2. 10MB 초과 파일, 이미지/PDF가 아닌 파일 선택 시 거부되는지 확인
3. 동일 이름+연락처로 두 번 제출 시 같은 폴더에 파일이 쌓이는지 확인(폴더가 중복 생성되지 않는지)
4. 동명이인(이름 같고 연락처 다름) 제출 시 폴더가 분리되는지 확인
5. `ROOT_FOLDER_ID`를 잘못된 값으로 설정해 업로드 실패를 재현하고, 실패 표시 + 재시도 동작 확인
6. 항목당 여러 파일(예: 신분증 2장) 업로드 시 모두 정상 저장되는지 확인
